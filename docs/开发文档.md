## 1. 系统概述

### 1.1 定位

建邺智课是面向 K12 的**课堂教学辅助平台**，核心范式为「**教师设计、AI 执行、学生受益**」。
教师在自己电脑上启动服务，学生在同一局域网内通过浏览器访问，完成四类学习活动；AI 负责个性化引导、自动批改与学情分析。

### 1.2 部署形态与运行拓扑

```
教师电脑（唯一服务器）
├─ Next.js 服务（默认 3000 端口）
├─ SQLite 数据库文件 prisma/dev.db
├─ 上传的附件目录（项目提交等的学生作品）
└─ AI 服务：通过 OpenAI 兼容接口调用外部大模型（需外网或内网模型服务）

学生设备（同一局域网）
└─ 浏览器访问 http://<教师电脑IP>:3000
```

**网络约束（重要）**：系统**仅在本地网络运行**。登录、注册、版本检查均已本地化，**不向任何外部服务器发送数据**。唯一的外部请求是 AI 模型接口调用，以及教师**主动点击**研究模块的「引用校验」时访问 Crossref。新增功能时**不得引入任何外部上报、统计、云依赖**。

### 1.3 与上游的关系

本仓库（`jieload/JYclass`）由开源项目 [`makerguan/quickclass-release`](https://github.com/makerguan/quickclass-release)（作者：管雪沨）改造而来，主要改造点：

- 品牌更名为「建邺智课」
- 移除登录遥测与外部网络依赖
- 新增完整 README

> 因此：改动时**不要盲目从上游同步**，两边已经分叉；如需引入上游更新，必须先比对差异再手工合并。

### 2.2 分层

```
页面层    src/app/teacher/**   src/app/student/**    （React 客户端组件为主）
           │  fetch('/api/...')  携带 Authorization: Bearer <JWT>

           │  鉴权 → 校验 → 调用业务层
业务层    src/lib/**                                  （AI、检索、研究、队列、认证）
           │  Prisma Client
数据层    prisma/schema.prisma → SQLite(prisma/dev.db)
```

### 2.3 关键设计决策（改动前必读）

| 决策 | 原因 | 约束 |
|---|---|---|
| **无 middleware，逐路由鉴权** | 简单、可控 | 每个 `/api/*` 路由**必须**自行校验 token 与角色 |
| **SQLite 写入串行化**（`dbWrite`） | SQLite 文件锁在高并发写入下会冲突 | **所有写操作必须包在 `dbWrite()` 里** |
| **AI 请求限流**（`aiQueue`） | 防止并发过高触发上游限流 | **所有 AI 调用必须经 `aiQueue.enqueue()`** |
| **AI 配置存数据库**（`SystemConfig`）而非环境变量 | 教师可在界面自助配置，无需改文件重启 | 变更后需 `reloadQueue` 让并发配置生效 |
| **知识库全量注入**而非 RAG 检索 | 教材场景追求答案不脱纲 | 单课堂知识库上限 5 万字 |
| **Prisma 关系名 PascalCase → 前端 camelCase** | 前端约定 | 接口层需做字段映射（见 10.1） |
| **构建忽略 TS/ESLint 错误** | 上游历史包袱 | `next.config.mjs` 中 `ignoreBuildErrors` / `ignoreDuringBuilds` 均为 true，**本地验证要自己跑 `npx tsc --noEmit`** |

## 3. 数据模型（Prisma）

数据库文件：`prisma/dev.db`（SQLite），Schema：`prisma/schema.prisma`。共约 30 个模型。

### 3.1 实体分组总览

| 分组 | 模型 | 说明 |
|---|---|---|
| **用户与班级** | `User`、`Class`、`TaskAssignment` | 师生账号、班级与邀请码、课堂-班级分配 |
| **课堂与活动容器** | `LearningTask`、`SubProject` | 课堂；学习活动（四类活动的挂载点） |
| **① 对话活动** | `PresetConversation`、`Conversation`、`Message` | 活动定义；学生对话会话；消息 |
| **② 课堂作业** | `QuizActivity`、`Question`、`QuizAttempt`、`QuestionAttempt` | 作业；题目；一次作答；单题作答 |
| **③ 互动探究** | `ExplorationActivity`、`ExplorationSubmission`、`ExplorationActionLog`、`AiCompanionMessage` | 探究活动；提交；操作行为日志；AI 伴学对话 |
| **④ 项目提交** | `ProjectSubmission`、`StudentProject`、`ProjectAttachment`、`ProjectLike` | 任务；学生作品；附件；点赞 |
| **学情分析** | `AIInsight`、`AnalysisTemplate`、`InsightTemplate` | 分析结果（带版本号）；分析模板；系统内置模板 |
| **教学研究** | `ResearchProject` | 论文/方案项目（含数据快照） |
| **知识库与材料** | `KnowledgeBase`、`Material`、`DocumentChunk` | 知识库；课堂材料；材料分块 |
| **其他** | `SystemConfig`、`LearningProgress`、`Evaluation` | 系统配置；学习进度；评价 |

### 3.2 核心关系链

```
User(教师) ──1:N──> LearningTask(课堂) ──N:M──> Class(班级, 经 TaskAssignment)
                         │
                         └──1:N──> SubProject(学习活动)
                                      ├──1:N──> PresetConversation ──1:N──> Conversation ──1:N──> Message
                                      ├──1:N──> QuizActivity ──1:N──> Question
                                      │              └──1:N──> QuizAttempt ──1:N──> QuestionAttempt
                                      ├──1:N──> ExplorationActivity ──1:N──> ExplorationSubmission ──1:N──> ExplorationActionLog
                                      │                            └──1:N──> AiCompanionMessage
                                      └──1:N──> ProjectSubmission ──1:N──> StudentProject ──1:N──> ProjectAttachment / ProjectLike

User(学生) ──N:1──> Class
LearningTask / SubProject / PresetConversation / QuizActivity / ExplorationActivity / ProjectSubmission
        └── 均可关联 AnalysisTemplate（studentInsightTemplateId / classInsightTemplateId）
AIInsight(分析结果) ── 关联 Class + User(可选) + scopeId，带 version 字段支持多版本
```

### 3.3 关键模型字段要点

**`SubProject`（学习活动）** — 四类活动的统一挂载点，含 `title / objectives / requirements / knowledgeBase / analysisPrompt / studentInsightTemplateId / classInsightTemplateId / sortOrder / enabled`。**新增一类学生活动，通常就是新增一个挂在这里的子实体。**

**`PresetConversation`（对话活动）** — 关键字段 `systemPrompt`（注入 AI 的系统提示词）、`analysisPrompt`、`classAnalysisPrompt`、`sortOrder`、`enabled`。

**`QuizActivity`（课堂作业）** — `status`（`INACTIVE` 未生效 / 已生效）、`passScore`、`quizDesignTemplateId`。注意：**编辑保存后 status 会回到 INACTIVE，需重新发布**。

**`ExplorationActivity`（互动探究）** — `htmlContent`（交互页面 HTML）、`enableSubmission`（是否可提交）、`enableAiCompanion` + `aiCompanionPrompt`（AI 伴学）、`questionsJson`（AI 生成的题目）。有学生提交后**内容与开关会被锁定**。

**`ProjectSubmission`（项目提交任务）** — `category`（`TEXT` / `IMAGE` / `VIDEO`）、`visibleToClass`、`allowLike`（开点赞自动开全班可见）、`fileSizeLimit`（MB，默认 10）。

**`StudentProject`（学生作品）** — `pinned`（置顶）、`hidden`（下架）；`@@unique([submissionId, studentId])` 保证一人一份。

**`SystemConfig`（系统配置，单行）** — `aiBaseUrl` / `aiApiKey` / `aiModel` / `aiMaxConcurrent` / `reasoningEnabled` / `insightDataSource` / `studentWordLimit` / `classWordLimit` / `requireStarRating` / `teacherName` / `grade` / `subject` / `conversationWarningThreshold` / `studentMotto`。

**`ResearchProject`（教学研究）** — `projectType`（`PAPER` / `PROPOSAL`）、`status`（`DRAFT` → `TITLES_READY` → `COMPLETED`）、`dataSnapshot`（创建时冻结的数据快照，保证论文可复现）、`contentText`（Markdown 全文）。

### 3.4 数据库操作

```bash
npm run db:push        # 同步 schema 到数据库（开发期改模型后执行）
npm run db:migrate     # 生成迁移（prisma migrate dev）
npm run db:seed        # 填充种子数据（含模板）
npm run db:reset       # 重置数据库（危险）
npx prisma generate    # 重新生成 Prisma Client
```

> 改 `schema.prisma` 后必须执行 `db:push` + `npx prisma generate`，否则类型不更新。

## 5. API 接口清单

**通用约定**

- 除认证接口外，均需请求头 `Authorization: Bearer <JWT>`
- 角色：`TEACHER` / `STUDENT`，不满足返回 `403`
- 错误返回 `{ error: string }`，成功返回数据对象或数组
- 动态段用 `[xxx]` 表示

### 5.1 认证 `api/auth/*`

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/auth/register` | 教师注册（本地完成，不校验外部账号） |
| POST | `/api/auth/login` | 教师登录（**已移除对外上报**） |
| POST | `/api/auth/student-login` | 学生登录 |
| GET | `/api/auth/check-users` | 检查是否已有账号（首次引导） |
| GET | `/api/auth/check-recovery` | 校验密保问题 |
| POST | `/api/auth/recover-password` | 通过密保重置密码 |
| POST | `/api/auth/recover-key` | 通过密钥文件恢复 |
| POST | `/api/auth/import-account` | 导入已有账号 |
| POST | `/api/auth/student/change-password` | 学生改密 |
| GET/PUT | `/api/auth/teacher/profile` | 教师资料 |

## 7. 核心模块详解

### 7.1 AI 接入 `src/lib/ai.ts`

```ts
getAIConfig()            // 从 SystemConfig 读配置；未配 API Key 抛错
createDashScopeClient()  // 用 createOpenAI({baseURL, apiKey}) 构造，返回 { chatModel, reasoningEnabled }
```

调用范式（以 `api/chat/route.ts` 为准）：

```ts
const { chatModel } = await createDashScopeClient();
const result = await aiQueue.enqueue(() =>
  streamText({ model: chatModel, system: systemPrompt, messages: formattedMessages })
);
for await (const chunk of result.textStream) { /* 逐块推给前端 */ }
```

**要点**：兼容任何 OpenAI 格式接口（通义千问 / DeepSeek / 智谱 / 本地模型）；支持多模态（图片转 `{type:'image', image, mediaType}`）；空响应与异常都要兜底文案。

### 7.2 AI 并发队列 `src/lib/ai-queue.ts`

单例 `aiQueue`，`enqueue(fn)` 排队执行；并发上限从 `SystemConfig.aiMaxConcurrent` 读取（首次使用时懒加载）。教师改配置后调用 `/api/system-config/reload-queue` 触发 `reloadConfig()`。

### 7.3 数据库写队列 `src/lib/db-queue.ts`

```ts
export const dbWriteQueue = new PQueue({ concurrency: 1 });   // 写操作串行
export async function dbWrite<T>(op: () => Promise<T>): Promise<T>
```

> **硬约束**：SQLite 高并发写入会文件锁冲突，所以**所有 `create / update / delete` 必须包进 `dbWrite()`**。读操作（`findMany` 等）可直接调用，且鼓励 `Promise.all` 并行。

### 7.4 认证 `src/lib/auth.ts`

- JWT（HS256），密钥取 `NEXTAUTH_SECRET`，有效期 7 天，`clockTolerance` 60s
- `createToken(payload)` / `verifyToken(token)`
- payload 约定：`{ userId, email, role, name }`
- 路由内鉴权范式：

```ts
const token = req.headers.get("authorization")?.replace("Bearer ", "");
if (!token) return NextResponse.json({ error: "未登录" }, { status: 401 });
const payload = await verifyToken(token);
if (!payload || payload.role !== "TEACHER")
  return NextResponse.json({ error: "无权限" }, { status: 403 });
```

### 7.5 提示词体系 `src/lib/prompts/`

| 文件 | 职责 |
|---|---|
| `index.ts` | 统一导出（新增提示词函数要在此登记） |
| `insight.ts` | **学情分析模板渲染**（`renderInsightTemplate` 等）、变量替换（`replaceTemplateVars` / `replaceConversationVars` / `replaceTaskVars`）、约束段（字数、星级） |
| `chat.ts` | 班级 AI 策略 `CLASS_AI_PROMPTS` / `getClassPromptByStrategy`、行为准则、知识库规则、图片提示 |
| `quiz.ts` | 作业题目生成与批改提示词 |
| `ai-companion.ts` | 互动探究的 AI 伴学提示词 |

模板变量替换是「模板驱动分析」的核心：教师自定义模板中的占位符在运行时被真实数据填充。

## 10. 扩展开发指南（重点）

### 10.1 新增一个 API 路由

在 `src/app/api/<域>/<资源>/route.ts` 或 `.../[id]/route.ts` 新建文件，套用统一模板：

```ts
import { NextRequest, NextResponse } from "next/server";
import { prisma } from "@/lib/prisma";
import { verifyToken } from "@/lib/auth";
import { dbWrite } from "@/lib/db-queue";

export async function GET(req: NextRequest) {
  try {
    const token = req.headers.get("authorization")?.replace("Bearer ", "");
    if (!token) return NextResponse.json({ error: "未登录" }, { status: 401 });
    const payload = await verifyToken(token);
    if (!payload) return NextResponse.json({ error: "无权限" }, { status: 403 });

    const data = await prisma.xxx.findMany({ where: { /* ... */ } });
    return NextResponse.json(data);
  } catch (error) {
    console.error("GET xxx error:", error);
    return NextResponse.json({ error: "服务器错误" }, { status: 500 });
  }
}

export async function POST(req: NextRequest) {
  // 同上鉴权 → 校验入参 → dbWrite(() => prisma.xxx.create({...}))
}
```

**约定**：① 一律 `try/catch` 兜底；② 写操作过 `dbWrite`；③ Prisma 关系名是 PascalCase，返回前端前做字段映射（参考 `api/tasks/route.ts` 的 `mapSubProject`）；④ 需 AI 的加 `aiQueue`。

## 11. 开发约定与注意事项

1. **不得引入外部网络依赖**。系统定位为「仅在本地网络使用」；禁止新增统计上报、云存储、外部 CDN 等。
2. **所有写操作走 `dbWrite()`**，所有 AI 调用走 `aiQueue.enqueue()`。
3. **每个 API 路由自行鉴权**（无全局 middleware），并校验角色。
4. **Prisma 关系名 → 前端字段名要映射**，不要把 PascalCase 直接丢给前端。
5. **不要改动的功能标识**（改了会坏）：
   - `#quickclass-submit-root` 等探究注入用的 CSS/JS 钩子
   - `quickclass_guide` 等 JSON 字段名
   - `quickclass-upgrade-staging` / `quickclass-backups` 等升级脚本临时路径
6. **构建忽略 TS/ESLint 错误**，因此提交前请自行执行 `npx tsc --noEmit` 与 `npm run lint`。
7. **改 `schema.prisma` 后必须 `db:push` + `npx prisma generate`**。
8. **单次改动只针对一个仓库、尽量只碰被指定的文件**，并保留可回退点（分支 + 版本记录）。

## 12. 常见问题与排障

| 现象 | 排查方向 |
|---|---|
| 「AI 服务未配置」 | 系统设置里未填 API Key，或 `SystemConfig` 无记录 |
| 学生看不到课堂 | 课堂 `status` 是否 ENABLED、是否分配到该班级、活动是否 `enabled` |
| AI 对话无响应 | AI 配置是否正确、`测试连接`是否通过、并发上限是否过低、模型是否支持图片输入 |
| 学情分析生成失败 | 需先有对话/作答数据；模板变量是否缺失；AI 服务是否可用 |
| 学情分析保存后丢关联 | 属历史 BUG，当前版本已修复（保存对话活动时保留关联） |
| 数据库写冲突 | 检查写操作是否漏了 `dbWrite()` |
| 类型报错但能构建 | 构建被配置忽略类型错误，请单独跑 `npx tsc --noEmit` |
| 删除 `dev.db` 后启动异常 | `npm run db:push` 重建，再 `npm run db:seed` |
